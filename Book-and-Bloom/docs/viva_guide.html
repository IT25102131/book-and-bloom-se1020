🌐 2. Core Architecture Questions (Asked from ANY Team Member)

Q1: Explain the High-Level Architecture of Book & Bloom.
Book & Bloom follows an Object-Oriented Three-Tier MVC Architecture: (1) Presentation Tier: JSP pages and responsive HTML5/CSS/JavaScript. (2) Application / Business Tier: An explicit Jakarta ApiServlet handles routing, session tokens, and CSRF protection before calling Domain Services (UserService, BookService, etc.). (3) Persistence Tier: Decoupled behind the StoreRepository interface supporting both atomic file storage (bookstore.txt) and MySQL relational storage (MysqlStoreRepository).
Q2: Why did you use Spring Boot with an explicit Jakarta Servlet together?
Spring Boot manages dependency injection, configuration, and the embedded Tomcat server. We wrote an explicit ApiServlet extending HttpServlet to demonstrate core Java Enterprise and Servlet fundamentals: manual HTTP method handling, Jackson JSON serialization, and explicit session / CSRF security lifecycle control.
Q3: Why is `BigDecimal` used for prices instead of `double` or `float`?
Binary floating-point types (double/float) cause precision loss due to base-2 representation (e.g. 0.1 + 0.2 = 0.30000000000000004). Financial systems require absolute precision, so Java's BigDecimal is used across all prices, subtotals, and delivery fee calculations.
Q4: How does Concurrency and Data Safety work?
Every mutation in StoreRepository.transaction() is thread-synchronized in memory. File operations use an OS FileLock (store.lock) and write to a .tmp file before executing an atomic move (ATOMIC_MOVE). In MySQL mode, relational transactions are managed under InnoDB with ACID transactions.

👥 3. Member-by-Member Viva Defense & Question Bank

Member 1: IT25102131 — User Management & Authentication Branch: feature/user-management-IT25102131

Core Java Classes: lk.bookbloom.model.User, Customer, AdminUser, UserService, Passwords

Assigned CRUD Operations:

  • Create: Customer account registration (/register ➔ UserService.register()).
  • Read: Customer profile view (/account), Admin customer table (/admin ➔ Users tab).
  • Update: Address, name, and contact details update (UserService.updateProfile()).
  • Delete: Delete customer account with order constraint check (UserService.delete()).

3 UI States: (1) Registration page with live validation, (2) Profile editor at /account, (3) Admin user list with search & roles.

Demonstrate Rejected Action: Try registering with an existing email (e.g. admin@bookbloom.lk). The system blocks it: "A customer with this email already exists."

Q: Where is Inheritance and Information Hiding in your module?
Customer and AdminUser both inherit from abstract class User, overriding user.role() polymorphically. Information hiding is enforced in User.publicProfile(), which strips out the sensitive passwordHash before JSON serialization.
Q: How are passwords secured?
Handled by Passwords.java using PBKDF2WithHmacSHA256 with a secure 16-byte random salt and 210,000 iterations. Passwords are never stored in plaintext.

  • Read: Catalog search/filter (/catalog), Book detail page (/book?id=...), Admin inventory list.
  • Update: Update book title, price, stock, description, format, and cover color.

Q: Where is Polymorphism in the Book module?
In Book.requiresShipping(). PrintedBook overrides it to return true (requires physical courier delivery), while EBook overrides it to return false. OrderService calls b.requiresShipping() polymorphically to calculate delivery fees!
Member 3: IT25102130 — Order, Checkout & Delivery Management Branch: feature/order-management-IT25102130

Core Java Classes: lk.bookbloom.model.Order, OrderLine, OrderService, DeliveryFeePolicy

Assigned CRUD Operations:

  • Create: Shopping bag checkout (/cart ➔ OrderService.create()).
  • Read: Customer order history (/orders), Admin dispatch dashboard (/admin ➔ Orders tab).
  • Update: Lifecycle transitions: PLACED ➔ PROCESSING ➔ COMPLETED, or CANCELLED.
  • Delete: Permanent deletion of cancelled orders (OrderService.delete()).

3 UI States: (1) Cart page with Free Delivery progress meter, (2) Order history with live courier tracking stepper, (3) Official Printable Tax Invoice with barcode.

Demonstrate Rejected Action: Try cancelling an already cancelled order. The state machine rejects it, guaranteeing stock is not restocked twice.

Q: How does atomic order cancellation restock inventory?
In OrderService.updateStatus(), when marked CANCELLED, each order line restores the book's stock: b.setStock(b.getStock() + line.getQuantity()). Both order state and inventory update inside the same synchronized transaction.

Q: What is the relationship between Category and Book?
It is a One-to-Many Association (Category 1 ──── * Book). One category holds many books, but each book belongs to one category via book.getCategoryId().
