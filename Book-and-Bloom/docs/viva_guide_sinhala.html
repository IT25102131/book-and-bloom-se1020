🌐 2. සාමාජිකයින් 6 දෙනාම දැනගත යුතු පොදු ප්‍රශ්න (General Architecture)

ප්‍රශ්නය 1: System එකේ High-Level Architecture එක පැහැදිලි කරන්න.
පිළිතුර: Book & Bloom පද්ධතිය Object-Oriented Three-Tier MVC Architecture එකක් මත ගොඩනගා ඇත: (1) Presentation Tier: JSP පිටු සහ dynamic JavaScript/CSS. (2) Application Tier: Jakarta ApiServlet එක Front Controller එකක් ලෙස ක්‍රියා කරමින් Session/CSRF check කර Business Services (UserService, BookService, ආදිය) වෙත delegate කරයි. (3) Persistence Tier: StoreRepository interface එක හරහා atomic file persistence (bookstore.txt) සහ relational MySQL persistence (MysqlStoreRepository) යන දෙකම decouple කර ඇත.
ප්‍රශ්නය 2: Spring Boot සමඟ explicit Jakarta Servlet එකක් පාවිච්චි කළේ ඇයි?
පිළිතුර: Spring Boot මඟින් Dependency Injection සහ embedded Tomcat server එක පහසු කරයි. නමුත් අපි HttpServlet subclass එකක් ලෙස explicit ApiServlet එකක් ලිව්වේ core Java Enterprise/Servlet මූලධර්ම (Manual HTTP routing, Jackson JSON parsing, HTTP status codes, explicit session rotation) අපට මනාව අවබෝධ වී ඇති බව පෙන්වීමටයි.
ප්‍රශ්නය 3: මිල ගණන් වලට `double` හෝ `float` වෙනුවට `BigDecimal` දැම්මේ ඇයි?
පිළිතුර: Binary floating-point types (double/float) වල base-2 නිරූපණය නිසා binary rounding errors ඇතිවේ (උදා: 0.1 + 0.2 = 0.30000000000000004). මූල්‍ය ගනුදෙනු වලදී ශතයක්වත් වැරදිය නොහැකි බැවින් Java හි BigDecimal යොදාගෙන සියලුම ගණනය කිරීම් සිදුකර ඇත.
ප්‍රශ්නය 4: Concurrency සහ Data Safety ආරක්ෂා කරන්නේ කොහොමද?
පිළිතුර: සෑම mutation එකක්ම StoreRepository.transaction() එක තුළ thread-synchronized වේ. File mode එකේදී OS-level FileLock (store.lock) භාවිතා කර තාවකාලික .tmp file එකකට ලියා පසුව ATOMIC_MOVE මඟින් replace කරයි. MySQL mode එකේදී InnoDB ACID transactions ක්‍රියාත්මක වේ.
